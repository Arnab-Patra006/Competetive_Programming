# Networking Protocols
- Network protocols defines the rules i.e two systems can communicate with each other.
✅ TCP-based protocols (reliable connection):
These use TCP underneath because they need reliable, ordered delivery:
HTTP / HTTPS → for websites
FTP → for file transfers
SMTP → for sending emails
IMAP / POP3 → for receiving emails
WebSocket → ✅ also uses TCP (not UDP!)

⚡ UDP-based protocols (fast, real-time, but less reliable):
These use UDP because they prioritize speed over guaranteed delivery:
DNS (usually uses UDP)
Video calls, online games, live streams
VoIP (voice over IP) apps like Zoom, Skype

# Application Layer - TCP vs UDP
## 1. Client-Server Model
### 1.1 HTTP / HTTPS (Hypertext Transfer Protocol / Secure)
📦 Used for: Browsing websites,1 connection,TCP
🔐 Why HTTPS: It encrypts the data, so no one can spy on what you're doing.
📌 Example: When you open https://google.com, your browser uses HTTPS to talk to Google servers.

### 1.2 FTP (File Transfer Protocol)
📦 Used for: Uploading/downloading files to/from a server, 2connections,TCP,Not used bcz its not encrypetd
❗ Why: Simple for transferring large files
📌 Example: A developer uploading a website to a hosting server might use FTP.

### 1.3 SMTP (Simple Mail Transfer Protocol)
📦 Used for: Sending emails,TCP
✉️ Why: It's the standard protocol for pushing mail out from your email client (like Gmail or Outlook).
📌 Example: When you hit "Send" on an email, SMTP takes it from you to the receiver’s server.

### 1.4 IMAP / POP3
📦 Used for: Receiving emails,TCP
🔄 IMAP: Syncs email across devices
📥 POP3: Downloads and removes email from server
📌 Example: IMAP keeps your email the same on phone & laptop, while POP3 stores it only on one device.

U1->Mail Send-->Mail Transfer Agent(U1-MTA)-->Mail Server-->U2-MTA->Mail Recieved-U2.

### 1.5 WebSocket
📦 Used for: Real-time two-way communication (chat apps, live data),TCP not UDP
🔄 Keeps a single connection open between client and server — both can send messages anytime
⚡ Fast and efficient — no repeated requests like HTTP
📌 Example: In a chat app, as soon as someone sends a message, it appears instantly on your screen without refreshing.
✅ WebSocket uses TCP, but behaves like real-time communication thanks to its persistent connection.


## 2.Peer-to-Peer (P2P) Model → WebRTC 
📦 Used for: Direct communication between users (video calls, file sharing),UDP
🔄 WebRTC (Web Real-Time Communication) enables browsers/devices to connect directly without a server in the middle (after initial setup)
📡 P2P = No central server for data — peers talk to each other directly
📌 Example: In a video call using WebRTC (like Google Meet or Discord), your browser streams audio/video directly to the other person's browser without going through a server (after signaling).
+ STUN, TURN, or Signaling servers — they help P2P actually work!

# Transport/Network Layer TCP vs UDP

## 🔄 TCP vs UDP (Transport Layer Protocols)

| Feature                | **TCP** (Transmission Control Protocol)         | **UDP** (User Datagram Protocol)             |
|------------------------|--------------------------------------------------|-----------------------------------------------|
| 📦 **Type**            | Connection-oriented                             | Connectionless                                |
| 🔁 **Reliability**     | ✅ Reliable (guarantees delivery & order)       | ❌ Not reliable (no delivery guarantee)       |
| 🧩 **Data Order**      | Maintains correct order                         | Packets may arrive out of order               |
| 🧾 **Acknowledgments** | Sends ACKs to confirm delivery                  | No acknowledgment mechanism                   |
| 🛠️ **Error Checking**  | Yes + Retransmits lost packets                  | Yes, but no retransmission                    |
| 🚀 **Speed**           | Slower (due to checks and confirmation)         | Faster (less overhead)                        |
| 💬 **Use Cases**       | Web, email, file transfer (needs complete data) | Streaming, gaming, voice (real-time preferred)|
| 🔢 **Header Size**     | Bigger (20–60 bytes)                            | Smaller (8 bytes)                             |
| 📌 **Example Protocols**| HTTP, HTTPS, FTP, SMTP                         | DNS, VoIP, online games, video calls          |
